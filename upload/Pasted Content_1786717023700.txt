# 2ndLife — Enterprise PRD + Engineering Execution Plan (v2)

**Product:** 2ndLife · **Company:** NahaLabs (Pty) Ltd
**Positioning:** Revenue Recovery Intelligence
**Tagline:** *Give your existing revenue a second life.*
**Companion assets (UI source of truth):** `2ndLife-logo-exact.png` (logo — use exactly as-is, never redesign), `landing-option2.png` (approved marketing site), `dashboard.png` (approved app shell).

## 1. Product Definition

2ndLife is a multi-tenant SaaS platform that finds revenue already inside a business's systems — inactive, stale, abandoned, unpaid or at-risk — and recovers it through intelligent, empathetic workflows (WhatsApp-first).

Core question: *"Who already wanted to buy, pay, renew or continue — and what stopped them?"*

Product loop: **Detect → Prioritize → Engage → Recover → Verify → Measure**

Initial recovery categories: stale leads, abandoned quotes, unconverted opportunities, lapsed customers, missed renewals, unpaid invoices, failed payments, dormant customers, expired offers, at-risk recurring revenue.

## 2. Go-To-Market & Verticals Rule

- **Architecture is horizontal.** No insurance concepts in core modules.
- **GTM vertical #1 = South African funeral & micro-insurance** (this is what the approved mockups depict). A vertical is a *configuration package* (terminology: policy/premium/lapsed; offer rules; compliance copy), e.g. `src/modules/verticals/funeral-insurance/`, never a fork of core logic.
- Later segments (subscriptions, financial services, education, healthcare, retail, B2B, professional services) = additional config packages only.

## 3. Brand & Design System (mandatory for all UI work)

- **Logo:** use the provided asset unchanged. Circular green cycle-arrow + "2ndLife" wordmark + "Revenue Recovery Intelligence" tagline.
- **Tokens (sampled from approved mockups; formalize in Tailwind config):**
  - `brand-950 #052E22` (hero/footer/sidebar), `brand-800 #0B3D2E`, `primary #16A34A`, `primary-soft #E9F6EE`, `accent-orange #F59E0B`, `ink #0B1220`, `bg #F7F8F9`, cards white.
- **Type:** Inter/Manrope; bold headings with a green accent span; sentence case; tabular numerals for money; `R` + comma thousands; SA English ("centre", "organisation").
- **Landing page must keep approved anchors:** headline "Give Your Revenue a Second Life."; 4 benefit bullets; "Secure. Compliant. Built for South African Businesses."; client logo strip; "Every lapsed policy is revenue you've already earned." problem section; "2ndLife Changes That." (WhatsApp AI, Ozow Instant EFT, smart workflows, recover more/spend less); 5 feature cards; 5-step How It Works (Upload → Score & Prioritize → Engage → Collect → Reactivate); testimonial block (R1.2M+ / 38% / 70%); WhatsApp demo chat card; footer with POPIA/Terms/Privacy.
- **Dashboard principles:** answer 4 questions first (recoverable? recovered? working? needs attention?); KPI cards with 7-day deltas; recovery funnel; operational charts only — no decorative widgets; quick actions; AI-insight strip. **Data-integrity rule: production funnels must be monotonic (each stage ≤ previous); mockup numbers are illustrative only.**

## 4. MVP Scope

**A. Onboarding:** Clerk auth; tenant creation; invitations; Owner/Admin/Member RBAC; business profile; vertical selection.

**B. Import (CSV):** column mapping; validation; preview; error report; dedupe; import history. Normalize SA phones to E.164 (`072 123 4567` → `+27721234567`, use `libphonenumber-js`); validate emails; flag WhatsApp-capable numbers.

**C. Recovery scoring — deterministic, explainable, no LLM:**

| Factor | Weight | Signal |
|---|---|---|
| Historical value | 25 | LTV / premium paid |
| Recency | 20 | days since last activity/lapse |
| Payment history | 15 | success ratio, failed-debit flags |
| Contactability | 15 | valid WhatsApp number, email |
| Offer availability | 10 | product live, rejoin window open |
| Prior engagement | 10 | responded before, opt-in status |
| Data completeness | 5 | required fields present |

Output: `score 0–100`, `estimated_value`, `reasons[]`, `risks[]`, `recommended_action`. Same input ⇒ same score (unit-tested).

**D. RecoveryOpportunity (core domain object):**

```ts
{ id, tenantId, customerId, sourceRecordId, category, score,
  estimatedValue, status, reason, recommendedAction, createdAt, updatedAt }
// statuses: new | qualified | queued | contacted | engaged | negotiating
// | converted | recovered | declined | unresponsive | failed | suppressed
```

**E. Customer 360:** contact details, score, estimated vs previous value, status, full event timeline (quote → failed payment → messages → replies → offer → payment).

**F. Campaigns:** name, vertical, audience filters, min score, channel, message strategy, send limits, business hours (default Mon–Fri 09:00–17:00 SAST), suppression (opt-outs/DNC/disputed), escalation rules, approved-offer rules, stop conditions.

**G. WhatsApp (primary channel):** Evolution API behind one typed adapter only.

```ts
interface MessagingProvider { sendMessage(...); sendTemplate(...); getStatus(...) }
// src/lib/integrations/evolution/ — no WhatsApp calls anywhere else
```

Inbound webhooks verified + idempotent; messages persisted; delivery states tracked; conversations linked to opportunities.

**H. AI Recovery Agent (Vercel AI SDK):** empathetic revenue-recovery conversations; intent detection; objection handling; presents *approved* options only; triggers payment flow; escalates to human; honours opt-out instantly. Tools (each: authenticate → tenant → authorize → Zod → service → audit):

```text
customer.get / customer.update / customer.opt_out
recovery.get_opportunity / recovery.update_status
campaign.get_context / product.get_available_options / pricing.get_allowed_offer
payment.create_request / payment.get_status
conversation.get_history / human.escalate
```

**Guardrails:** AI may read context/approved offers/payment status; may send messages, create payment requests, update status, escalate, opt out. AI may **never** invent prices/discounts/terms, confirm payments, mark revenue recovered, delete data, bypass limits, ignore opt-outs. **Privacy:** context minimization — only task-relevant fields sent to the model (POPIA by design).

**I. Payments:** `PaymentProvider` abstraction, **Ozow Instant EFT first**. Confirmation **only** via verified, idempotent webhooks: `webhook → verify → persist → PaymentConfirmed → opportunity=recovered → analytics updated`. Browser redirects are never proof of payment.

**J. Attribution:** Contacted / Engaged / Converted / **Recovered (verified only)**. Metrics: pipeline counts, potential vs expected vs actual recovered revenue, recovery & conversion rates, revenue per opportunity, campaign ROI, AI resolution rate, escalation rate, opt-out rate.

**K. Screen inventory (match mockups):** marketing landing; auth; onboarding; import wizard; customers list; Customer 360; opportunities queue; campaigns list + builder; conversations inbox (badge counts); payments; analytics; integrations; settings; dashboard per `dashboard.png`.

## 5. Domain Events

`CustomerImported, RecoveryOpportunityCreated, RecoveryScoreCalculated, CampaignCreated, CampaignStarted, MessageSent, MessageReceived, CustomerEngaged, OfferPresented, PaymentRequested, PaymentConfirmed, RecoveryConverted, RevenueRecovered, ConversationEscalated, CustomerOptedOut` — persisted/auditable.

## 6. Mandatory NahaLabs Stack

Next.js App Router · TypeScript strict · Tailwind + shadcn/ui · React Hook Form + Zod · TanStack Query · Zustand only where needed · Clerk · Neon PostgreSQL + Drizzle · Vercel AI SDK (never raw provider SDKs; no LangChain/LlamaIndex) · Vercel Blob · Upstash Redis · Evolution API on Render · Vercel deploy · Playwright E2E. **No** custom auth, microservices, Kubernetes, or split repos.

**Repository:**

```text
src/app/(marketing)/ (app)/dashboard customers opportunities campaigns conversations analytics settings
src/app/api/v1/ webhooks/evolution webhooks/payments jobs/ mcp/[...route]/
src/modules/ tenants users customers imports recovery campaigns conversations messaging payments analytics ai audit
src/lib/db/schema queries · lib/integrations/evolution payments · lib/ai/providers tools prompts evals · lib/events security cache
src/shared/ types validation errors constants
```

**Database (every business table has `tenant_id`; isolation enforced in the data-access layer; UI never touches DB; route handlers stay thin):** tenants, users, memberships, customers, customer_contacts, customer_events, imports, import_records, import_errors, recovery_opportunities, recovery_scores, recovery_events, campaigns, campaign_members, campaign_events, conversations, conversation_messages, payment_requests, payments, activity_events, audit_logs, ai_conversations, ai_tool_calls, integration_connections, webhook_events.

**MCP (`/api/mcp/[...route]`):** tools `customers.search/get, recovery.list/get, campaigns.list/get, conversations.get, payments.get, analytics.summary, diagnostics.run` through pipeline Clerk → Tenant → RBAC → tool authorization → Zod → service → audit. Never raw DB access.

**Security/POPIA:** server-side authorization, RBAC, Zod everywhere, rate limiting, webhook verification + idempency, audit logs, CSP/HSTS/secure headers, sanitized size-limited uploads, secret management, dependency scanning, consent + opt-out handling, data minimization, retention rules.

### `src/lib/db/index.ts`

```ts
import { drizzle } from "drizzle-orm/neon-http";
import { neon } from "@neondatabase/serverless";
import * as schema from "./schema";

type DbClient = ReturnType<typeof drizzle<typeof schema>>;

let _db: DbClient | null = null;
let _checked = false;

function getDb(): DbClient | null {
  if (_checked) return _db;
  _checked = true;
  const url = process.env.DATABASE_URL;
  if (!url) return null;
  _db = drizzle(neon(url), { schema });
  return _db;
}

export const db = new Proxy({} as DbClient, {
  get(_t, prop) {
    const client = getDb();
    if (!client) {
      throw new Error("DATABASE_NOT_CONFIGURED");
    }
    const value = (client as never as Record<string | symbol, unknown>)[prop];
    return typeof value === "function" ? value.bind(client) : value;
  },
});

export const isDbConfigured = () => Boolean(process.env.DATABASE_URL);
```

> Using a `Proxy` keeps the call site ergonomic (`db.query.tenants.findFirst()`) while still letting `env -i npm run build` pass — the proxy only touches env when a method is invoked at runtime, never at module load.

```ts
"use server";

import { auth } from "@clerk/nextjs/server";
import { eq } from "drizzle-orm";
import { db } from "@/lib/db";
import { tenants, users, memberships } from "@/lib/db/schema";
import { AppError } from "@/shared/errors/types";
import { logger } from "@/lib/logging/logger";

export type TenantContext = {
  tenantId: string;
  userId: string;
  role: "owner" | "admin" | "member";
};

export async function getTenantContext(): Promise<TenantContext> {
  const { userId: clerkId } = auth();
  if (!clerkId) throw new AppError("UNAUTHENTICATED", 401, "Not authenticated");

  if (!process.env.DATABASE_URL) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  const user = await db.query.users.findFirst({ where: eq(users.clerkId, clerkId) });
  if (!user) throw new AppError("USER_NOT_FOUND", 404, "User profile not found");

  const membership = await db.query.memberships.findFirst({ where: eq(memberships.userId, user.id) });
  if (!membership) throw new AppError("NO_TENANT", 404, "User has no tenant");

  return { tenantId: membership.tenantId, userId: user.id, role: membership.role };
}

export async function createTenantWithOwner(input: {
  clerkId: string;
  email?: string;
  fullName?: string;
  tenantName: string;
}): Promise<TenantContext> {
  if (!process.env.DATABASE_URL) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  // Idempotent: reuse user if already exists
  let user = await db.query.users.findFirst({ where: eq(users.clerkId, input.clerkId) });
  if (!user) {
    const [created] = await db
      .insert(users)
      .values({ clerkId: input.clerkId, email: input.email, fullName: input.fullName })
      .returning();
    user = created;
  }

  const existing = await db.query.memberships.findFirst({ where: eq(memberships.userId, user!.id) });
  if (existing) {
    return { tenantId: existing.tenantId, userId: user!.id, role: existing.role };
  }

  const [tenant] = await db.insert(tenants).values({ name: input.tenantName }).returning();
  const [membership] = await db
    .insert(memberships)
    .values({ tenantId: tenant!.id, userId: user!.id, role: "owner" })
    .returning();

  logger("info", "tenant.created", { tenantId: tenant!.id, userId: user!.id });

  return { tenantId: membership.tenantId, userId: user!.id, role: membership.role };
}
```

### `src/modules/tenants/rbac.ts`

```ts
"use server";

import { auth } from "@clerk/nextjs/server";
import { eq } from "drizzle-orm";
import { db } from "@/lib/db";
import { memberships, users } from "@/lib/db/schema";
import { AppError } from "@/shared/errors/types";

const HIERARCHY: Record<string, number> = { owner: 3, admin: 2, member: 1 };

export async function requireRole(allowed: Array<"owner" | "admin" | "member">) {
  const { userId: clerkId } = auth();
  if (!clerkId) throw new AppError("UNAUTHENTICATED", 401);

  if (!process.env.DATABASE_URL) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  const user = await db.query.users.findFirst({ where: eq(users.clerkId, clerkId) });
  if (!user) throw new AppError("USER_NOT_FOUND", 404);

  const membership = await db.query.memberships.findFirst({ where: eq(memberships.userId, user.id) });
  if (!membership) throw new AppError("NO_TENANT", 404);

  const userLevel = HIERARCHY[membership.role] ?? 0;
  const required = Math.min(...allowed.map((r) => HIERARCHY[r]));
  if (userLevel < required) {
    throw new AppError("FORBIDDEN", 403, "Insufficient role");
  }
  return { tenantId: membership.tenantId, userId: user.id, role: membership.role };
}
```

### `src/shared/errors/types.ts`

```ts
export class AppError extends Error {
  constructor(
    public readonly code: string,
    public readonly status: number = 500,
    message?: string
  ) {
    super(message ?? code);
    this.name = "AppError";
  }

  toJSON() {
    return { error: { code: this.code, message: this.message } };
  }
}

export function toErrorResponse(err: unknown): { status: number; body: { error: { code: string; message: string } } } {
  if (err instanceof AppError) {
    return { status: err.status, body: err.toJSON() };
  }
  // Never surface raw DB / internal errors
  return {
    status: 500,
    body: { error: { code: "INTERNAL_ERROR", message: "An unexpected error occurred" } },
  };
}

export async function withRouteHandler<T>(
  fn: () => Promise<T>
): Promise<{ status: number; body: T | { error: { code: string; message: string } } }> {
  try {
    const data = await fn();
    return { status: 200, body: data };
  } catch (err) {
    return toErrorResponse(err);
  }
}
```

### `src/lib/logging/logger.ts`

```ts
type LogLevel = "debug" | "info" | "warn" | "error";

type LogContext = {
  requestId?: string;
  tenantId?: string;
  userId?: string;
  [k: string]: unknown;
};

// PII / secret denylist — keys are stripped from logs
const REDACT_KEYS = new Set([
  "password", "token", "secret", "apiKey", "api_key", "authorization",
  "email", "phone", "idNumber", "clerkId",
]);

function redact(meta: Record<string, unknown>): Record<string, unknown> {
  const out: Record<string, unknown> = {};
  for (const [k, v] of Object.entries(meta)) {
    if (REDACT_KEYS.has(k)) out[k] = "[redacted]";
    else if (v && typeof v === "object" && !Array.isArray(v)) out[k] = redact(v as Record<string, unknown>);
    else out[k] = v;
  }
  return out;
}

export function logger(level: LogLevel, message: string, ctx: LogContext = {}) {
  const entry = {
    ts: new Date().toISOString(),
    level,
    message,
    ...redact(ctx as Record<string, unknown>),
  };
  const line = JSON.stringify(entry);
  if (level === "error") console.error(line);
  else if (level === "warn") console.warn(line);
  else console.log(line);
}
```

```ts
import { NextResponse } from "next/server";
import { auth } from "@clerk/nextjs/server";
import { z } from "zod";
import { createTenantWithOwner } from "@/modules/tenants/service";
import { toErrorResponse } from "@/shared/errors/types";

export const dynamic = "force-dynamic";

const Body = z.object({
  companyName: z.string().min(2).max(120),
  email: z.string().email().optional(),
  fullName: z.string().max(255).optional(),
});

export async function POST(req: Request) {
  try {
    const { userId: clerkId } = auth();
    if (!clerkId) return NextResponse.json({ error: { code: "UNAUTHENTICATED", message: "Not authenticated" } }, { status: 401 });

    const parsed = Body.safeParse(await req.json().catch(() => null));
    if (!parsed.success) {
      return NextResponse.json({ error: { code: "VALIDATION_ERROR", message: parsed.error.message } }, { status: 400 });
    }

    const ctx = await createTenantWithOwner({ clerkId, ...parsed.data });
    return NextResponse.json({ tenantId: ctx.tenantId });
  } catch (err) {
    const { status, body } = toErrorResponse(err);
    return NextResponse.json(body, { status });
  }
}
```

### 2. Utilities (`src/lib/utils.ts`)
```ts
import { type ClassValue, clsx } from "clsx";
import { twMerge } from "tailwind-merge";
import { parsePhoneNumber } from "libphonenumber-js";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}

export function formatZAR(amount: number | string) {
  const num = typeof amount === "string" ? parseFloat(amount) : amount;
  return new Intl.NumberFormat("en-ZA", {
    style: "currency",
    currency: "ZAR",
    minimumFractionDigits: 2,
  }).format(num || 0);
}

export function normalizePhoneZA(phone: string): string | null {
  if (!phone) return null;
  try {
    // If it doesn't start with +, assume SA and strip leading 0
    const formatted = phone.startsWith("+") ? phone : `+27${phone.replace(/^0/, "")}`;
    const parsed = parsePhoneNumber(formatted, "ZA");
    return parsed && parsed.isValid() ? parsed.number : null;
  } catch {
    return null;
  }
}
```

```ts
import { NextResponse } from "next/server";
import { parse } from "papaparse";

export const dynamic = "force-dynamic";

export async function POST(req: Request) {
  try {
    const formData = await req.formData();
    const file = formData.get("file") as File;
    if (!file) return NextResponse.json({ error: "No file" }, { status: 400 });

    const text = await file.text();
    const result = parse(text, { header: true, skipEmptyLines: true });

    // Return headers and first 5 rows for mapping preview
    const headers = result.meta.fields || [];
    const sample = result.data.slice(0, 5);

    return NextResponse.json({ headers, sample, totalRows: result.data.length });
  } catch (err) {
    return NextResponse.json({ error: "Parse failed" }, { status: 500 });
  }
}
```

**`src/app/api/v1/imports/commit/route.ts`** (Handles mapping & insertion)
```ts
import { NextResponse } from "next/server";
import { getTenantContext } from "@/modules/tenants/service";
import { createCustomer } from "@/modules/customers/service";
import { normalizePhoneZA } from "@/lib/utils";
import { toErrorResponse } from "@/shared/errors/types";
import { parse } from "papaparse";

export const dynamic = "force-dynamic";

export async function POST(req: Request) {
  try {
    const ctx = await getTenantContext();
    const { file, mapping } = await req.json();
    
    // In a real app, you'd stream this or use a queue for large files.
    // For Phase 3 MVP, we parse in memory.
    const result = parse(file, { header: true, skipEmptyLines: true });
    
    let valid = 0;
    let errors = 0;

    for (const row of result.data as any[]) {
      const phone = normalizePhoneZA(row[mapping.phone]);
      if (!phone) {
        errors++;
        continue;
      }

      await createCustomer(ctx, {
        fullName: row[mapping.fullName] || "Unknown",
        phone,
        email: row[mapping.email] || null,
        status: row[mapping.status] || "active",
        metadata: { source: "csv_import" }
      });
      valid++;
    }

    return NextResponse.json({ success: true, valid, errors });
  } catch (err) {
    const { status, body } = toErrorResponse(err);
    return NextResponse.json(body, { status });
  }
}
```

```tsx
"use client";

import { useState } from "react";
import { toast } from "sonner";
import { Button } from "@/components/ui/button";
import { Card } from "@/components/ui/card";

type Step = "upload" | "map" | "validate" | "preview";
const steps: Step[] = ["upload", "map", "validate", "preview"];

export function ImportWizard() {
  const [currentStep, setCurrentStep] = useState<Step>("upload");
  const [file, setFile] = useState<File | null>(null);
  const [csvData, setCsvData] = useState<{ headers: string[]; sample: any[]; totalRows: number } | null>(null);
  const [mapping, setMapping] = useState<{ fullName?: string; phone?: string; email?: string; status?: string }>({});
  const [committing, setCommitting] = useState(false);

  const handleUpload = async () => {
    if (!file) return;
    const formData = new FormData();
    formData.append("file", file);

    const res = await fetch("/api/v1/imports", { method: "POST", body: formData });
    if (!res.ok) return toast.error("Failed to parse CSV");
    
    const data = await res.json();
    setCsvData(data);
    
    // Auto-map basic fields
    const findHeader = (keys: string[]) => data.headers.find((h: string) => keys.some(k => h.toLowerCase().includes(k)));
    setMapping({
      fullName: findHeader(["name", "full_name", "customer"]),
      phone: findHeader(["phone", "mobile", "cell"]),
      email: findHeader(["email"]),
      status: findHeader(["status", "policy_status"]),
    });
    
    setCurrentStep("map");
  };

  const handleCommit = async () => {
    if (!file || !mapping.phone) return toast.error("Phone mapping is required");
    setCommitting(true);
    
    const text = await file.text();
    const res = await fetch("/api/v1/imports/commit", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ file: text, mapping })
    });

    setCommitting(false);
    if (!res.ok) return toast.error("Import failed");
    
    const result = await res.json();
    toast.success(`Import complete: ${result.valid} valid, ${result.errors} errors`);
    setCurrentStep("validate"); // For MVP we just show validation step on success
  };

  return (
    <div className="space-y-6">
      {/* Stepper UI */}
      <div className="flex gap-4">
        {steps.map((s, i) => (
          <div key={s} className={`flex items-center gap-2 text-sm ${currentStep === s ? "font-bold" : "text-muted-foreground"}`}>
            <span className={`flex h-6 w-6 items-center justify-center rounded-full ${currentStep === s ? "bg-primary text-white" : "bg-muted"}`}>{i+1}</span>
            {s.charAt(0).toUpperCase() + s.slice(1)}
          </div>
        ))}
      </div>

      {currentStep === "upload" && (

          </div>

            <Button disabled={!mapping.phone} onClick={() => setCurrentStep("preview")}>Continue to Preview →</Button>

      )}

      {currentStep === "preview" && csvData && (
```

### 1. Scoring Engine (`src/modules/recovery/scoring.ts`)

This is a pure function. It contains no references to `db`, `process.env`, or `new Date()`. This guarantees that it is deterministic and easily unit-testable.

```ts
export type ScoringInput = {
  historicalValue: number;       // in ZAR
  inactiveDays: number;          // days since last activity
  paymentSuccessRatio: number;   // 0.0 to 1.0
  hasValidPhone: boolean;        // E.164 validated
  hasEmail: boolean;
  offerAvailable: boolean;       // product live, rejoin window open
  respondedBefore: boolean;      // opted in / replied in past
  dataComplete: boolean;         // all required fields present
};

export type ScoringResult = {
  score: number;                 // 0-100
  estimatedValue: number;        // projected recovery value
  reasons: string[];             // e.g., "+25 High historical value"
  risks: string[];               // e.g., "-5 Inactive > 6 months"
  recommendedAction: string;
};

export function calculateRecoveryScore(input: ScoringInput): ScoringResult {
  let score = 0;
  const reasons: string[] = [];
  const risks: string[] = [];

  // 1. Historical value (Max 25)
  if (input.historicalValue > 5000) {
    score += 25;
    reasons.push("+25 High historical value");
  } else if (input.historicalValue > 1000) {
    score += 15;
    reasons.push("+15 Moderate historical value");
  } else {
    score += 5;
    reasons.push("+5 Low historical value");
  }

  // 2. Recency (Max 20)
  if (input.inactiveDays < 90) {
    score += 20;
    reasons.push("+20 Recent activity");
  } else if (input.inactiveDays < 180) {
    score += 15;
    reasons.push("+15 Inactive < 6 months");
  } else if (input.inactiveDays < 365) {
    score += 10;
    reasons.push("+10 Inactive < 1 year");
    risks.push("-5 Inactive > 6 months");
  } else {
    score += 5;
    reasons.push("+5 Long inactivity");
    risks.push("-10 Inactive > 1 year");
  }

  // 3. Payment history (Max 15)
  const paymentScore = Math.round(input.paymentSuccessRatio * 15);
  score += paymentScore;
  reasons.push(`+${paymentScore} Payment success ratio (${(input.paymentSuccessRatio * 100).toFixed(0)}%)`);
  if (input.paymentSuccessRatio < 0.5) {
    risks.push("-5 Poor payment history");
  }

  // 4. Contactability (Max 15)
  let contactScore = 0;
  if (input.hasValidPhone) {
    contactScore += 10;
    reasons.push("+10 Valid WhatsApp number");
  }
  if (input.hasEmail) {
    contactScore += 5;
    reasons.push("+5 Valid email");
  }
  score += contactScore;
  if (contactScore === 0) {
    risks.push("-15 No valid contact methods");
  }

  // 5. Offer availability (Max 10)
  if (input.offerAvailable) {
    score += 10;
    reasons.push("+10 Offer available");
  } else {
    risks.push("-10 No active offer");
  }

  // 6. Prior engagement (Max 10)
  if (input.respondedBefore) {
    score += 10;
    reasons.push("+10 Prior engagement");
  }

  // 7. Data completeness (Max 5)
  if (input.dataComplete) {
    score += 5;
    reasons.push("+5 Complete data");
  } else {
    risks.push("-5 Incomplete data");
  }

  // Clamp score to 0-100
  const finalScore = Math.max(0, Math.min(100, score));
  const estimatedValue = input.historicalValue * (finalScore / 100);

  let recommendedAction = "Do not prioritize";
  if (finalScore >= 80) {
    recommendedAction = "Engage immediately with premium offer";
  } else if (finalScore >= 50) {
    recommendedAction = "Engage with standard restart offer";
  } else if (finalScore >= 30) {
    recommendedAction = "Include in bulk low-priority campaign";
  }

  return {
    score: finalScore,
    estimatedValue,
    reasons,
    risks,
    recommendedAction,
  };
}
```

```ts
export async function createCampaign(ctx: Ctx, data: any) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  const [campaign] = await db.insert(campaigns).values({
    ...data,
    tenantId: ctx.tenantId,
    status: "draft"
  }).returning();
  return campaign;
}

export async function listCampaigns(ctx: Ctx) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  return db.query.campaigns.findMany({
    where: eq(campaigns.tenantId, ctx.tenantId)
  });
}

export async function qualifyAudience(ctx: Ctx, filters: { minScore?: number }) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  
  // Drizzle JSONB filtering can be tricky depending on dialect. 
  // For Neon (Postgres), we can cast and compare, or fetch and filter in JS for MVP.
  // Let's fetch non-suppressed and filter in JS to avoid dialect-specific raw SQL for now.
  const allCustomers = await db.query.customers.findMany({
    where: and(
      eq(customers.tenantId, ctx.tenantId),
      eq(customers.isSuppressed, false)
    )
  });

  if (!filters.minScore) return allCustomers;

  return allCustomers.filter(c => {
    const score = c.metadata?.score || 0;
    return score >= filters.minScore;
  });
}

export async function dryRunCampaign(ctx: Ctx, id: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  
  const campaign = await db.query.campaigns.findFirst({
    where: and(eq(campaigns.id, id), eq(campaigns.tenantId, ctx.tenantId))
  });
  if (!campaign) throw new AppError("NOT_FOUND", 404, "Campaign not found");

  const audience = await qualifyAudience(ctx, campaign.audienceFilters as any);
  
  const [updated] = await db.update(campaigns).set({
    status: "dry_run_passed",
    metadata: { dryRunCount: audience.length }
  }).where(eq(campaigns.id, id)).returning();

  return { campaign: updated, audienceCount: audience.length };
}

export async function launchCampaign(ctx: Ctx, id: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  
  const campaign = await db.query.campaigns.findFirst({
    where: and(eq(campaigns.id, id), eq(campaigns.tenantId, ctx.tenantId))
  });
  if (!campaign) throw new AppError("NOT_FOUND", 404, "Campaign not found");

  if (campaign.status !== "dry_run_passed") {
    throw new AppError("DRY_RUN_REQUIRED", 409, "Must pass dry-run before launch");
  }

  const [updated] = await db.update(campaigns).set({
    status: "active"
  }).where(eq(campaigns.id, id)).returning();

  return updated;
}
```

## Top 5 Risks for Phase 5
1. **JSONB Filtering Performance** — Querying `metadata->>score` in JS (fetching all then filtering) is fine for MVP (<10k records). In production, this will cause memory spikes. Phase 11 will require raw SQL or generated columns for indexed JSONB querying.
2. **Race Conditions** — If a user clicks "Launch" twice rapidly, it could bypass the `dry_run_passed` check. We need optimistic locking or a DB-level constraint eventually.
3. **Missing `campaign_members` table** — The PRD mentions a `campaign_members` join table. We are skipping it for MVP and just querying `customers` on the fly. We will need to materialize this when we actually send messages in Phase 6.
4. **Business Hours Logic** — I hardcoded the SAST text in the UI, but there is no server-side enforcement of business hours yet. That logic belongs in the message dispatch queue (Phase 6).
5. **Zod Coercion** — `z.coerce.number()` is used for the form inputs. If the user types non-numeric characters, it resolves to `NaN` which Zod catches, but the error message might be generic. Good enough for MVP.

Report back once Vercel is green and you've tested the dry-run flow. Then we move to **Phase 6 (WhatsApp & Evolution API)**.

### 2. Evolution Adapter

**`src/lib/integrations/evolution/adapter.ts`**
```ts
import { AppError } from "@/shared/errors/types";

export interface MessagingProvider {
  sendMessage(to: string, body: string): Promise<{ externalId: string }>;
}

export class EvolutionAdapter implements MessagingProvider {
  private baseUrl: string;
  private apiKey: string;
  private instance: string;

  constructor() {
    this.baseUrl = process.env.EVOLUTION_API_URL || "";
    this.apiKey = process.env.EVOLUTION_API_KEY || "";
    this.instance = process.env.EVOLUTION_INSTANCE_NAME || "2ndlife";
  }

  async sendMessage(to: string, body: string): Promise<{ externalId: string }> {
    if (!this.baseUrl || !this.apiKey) {
      throw new AppError("EVOLUTION_NOT_CONFIGURED", 503, "Evolution API not configured");
    }

    const url = `${this.baseUrl}/message/sendText/${this.instance}`;
    const res = await fetch(url, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "apikey": this.apiKey,
      },
      body: JSON.stringify({
        number: to,
        options: { delay: 1200, presence: "composing" },
        textMessage: { text: body },
      }),
    });

    if (!res.ok) {
      const errText = await res.text();
      throw new AppError("EVOLUTION_SEND_FAILED", 502, `Failed to send message: ${errText}`);
    }

    const data = await res.json();
    return { externalId: data.key?.id || crypto.randomUUID() };
  }
}

// Singleton instance
export const evolution = new EvolutionAdapter();
```

### 3. Conversations Service

```ts
import { eq, and } from "drizzle-orm";
import { db } from "@/lib/db";
import { conversations, conversationMessages, webhookEvents, customers } from "@/lib/db/schema/conversations";
import { AppError } from "@/shared/errors/types";
import { evolution } from "@/lib/integrations/evolution/adapter";

type Ctx = { tenantId: string };

export async function listConversations(ctx: Ctx) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  return db.query.conversations.findMany({
    where: eq(conversations.tenantId, ctx.tenantId),
    with: {
      customer: true,
    },
    orderBy: (conversations, { desc }) => [desc(conversations.createdAt)],
    limit: 50,
  });
}

export async function getConversationMessages(ctx: Ctx, convId: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  return db.query.conversationMessages.findMany({
    where: and(eq(conversationMessages.conversationId, convId), eq(conversationMessages.tenantId, ctx.tenantId)),
    orderBy: (conversationMessages, { asc }) => [asc(conversationMessages.createdAt)],
  });
}

export async function sendMessage(ctx: Ctx, convId: string, body: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  
  const conv = await db.query.conversations.findFirst({
    where: and(eq(conversations.id, convId), eq(conversations.tenantId, ctx.tenantId)),
    with: { customer: true }
  });
  if (!conv) throw new AppError("NOT_FOUND", 404, "Conversation not found");

  // 1. Call Evolution API
  const { externalId } = await evolution.sendMessage(conv.customer.phone, body);

  // 2. Persist in DB
  const [message] = await db.insert(conversationMessages).values({
    tenantId: ctx.tenantId,
    conversationId: convId,
    role: "ai",
    body,
    status: "sent",
    externalId,
  }).returning();

  return message;
}

export async function receiveMessage(ctx: Ctx, payload: any) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  // Evolution payload structure (simplified for MVP)
  const externalId = payload.key?.id;
  const fromPhone = payload.key?.remoteJid?.split("@")[0];
  const body = payload.message?.conversation || payload.message?.extendedTextMessage?.text;

  if (!externalId || !fromPhone || !body) {
    throw new AppError("INVALID_WEBHOOK", 400, "Missing required fields");
  }

  // 1. Idempotency check
  const existing = await db.query.webhookEvents.findFirst({
    where: eq(webhookEvents.externalId, externalId)
  });
  if (existing) {
    return { status: "duplicate" };
  }

  // 2. Find customer by phone
  const customer = await db.query.customers.findFirst({
    where: and(eq(customers.tenantId, ctx.tenantId), eq(customers.phone, fromPhone))
  });

  let conversation;

  if (customer) {
    // 3. Find or create conversation
    conversation = await db.query.conversations.findFirst({
      where: and(eq(conversations.customerId, customer.id), eq(conversations.tenantId, ctx.tenantId))
    });

    if (!conversation) {
      const [newConv] = await db.insert(conversations).values({
        tenantId: ctx.tenantId,
        customerId: customer.id,
        status: "active"
      }).returning();
      conversation = newConv;
    }

    // 4. Persist webhook event
    await db.insert(webhookEvents).values({
      tenantId: ctx.tenantId,
      externalId,
      provider: "evolution",
      payload
    });

    // 5. Persist message
    const [message] = await db.insert(conversationMessages).values({
      tenantId: ctx.tenantId,
      conversationId: conversation.id,
      role: "customer",
      body,
      status: "received",
      externalId,
    }).returning();

    return { status: "created", message };
  }

  // Unknown customer, persist webhook but ignore message
  await db.insert(webhookEvents).values({
    tenantId: ctx.tenantId,
    externalId,
    provider: "evolution",
    payload
  });

  return { status: "unknown_customer" };
}
```

## Top 5 Risks for Phase 6
1. **Evolution API Payload Structure** — The `receiveMessage` function assumes a specific WhatsApp/Evolution JSON structure (`payload.key.id`, etc.). Evolution v2 might send a slightly different format. We'll need to test with a real Evolution instance.
2. **Tenant Resolution from Webhook** — Webhooks don't inherently know which tenant they belong to. I used `DEFAULT_TENANT_ID` for MVP. In production, we need to map Evolution Instance names to Tenant IDs.
3. **Polling Overhead** — The UI polls every 3-5 seconds. This is fine for MVP, but Vercel will throttle if we get many users. We should switch to Server-Sent Events (SSE) or WebSockets in Phase 11.
4. **Missing `DEFAULT_TENANT_ID`** — If you don't set this in `.env`, the webhook route will 500. Add it to `.env.example`.
5. **Missing Conversation Start** — If a customer texts in without an existing conversation, we create one. But if they have no `Customer` record, we drop the message. We should create a "Lead" customer in that case later.

Report back once Vercel is green and tests pass. Then we move to **Phase 7 (AI Recovery Agent)**.

### 4. Chat API Route

**`src/app/api/v1/conversations/[id]/chat/route.ts`**
```ts
import { streamText, convertToCoreMessages, Message } from "ai";
import { NextResponse } from "next/server";
import { getTenantContext } from "@/modules/tenants/service";
import { getConversationMessages, sendMessage } from "@/modules/conversations/service";
import { getModel } from "@/lib/ai/providers";
import { RECOVERY_AGENT_SYSTEM_PROMPT } from "@/lib/ai/prompts";
import { createRecoveryTools } from "@/lib/ai/tools";
import { toErrorResponse } from "@/shared/errors/types";
import { db } from "@/lib/db";
import { conversationMessages } from "@/lib/db/schema/conversations";
import { AppError } from "@/shared/errors/types";

export const dynamic = "force-dynamic";
export const runtime = "nodejs";

export async function POST(req: Request, { params }: { params: { id: string } }) {
  try {
    const ctx = await getTenantContext();
    const { id: conversationId } = params;
    const { messages }: { messages: Message[] } = await req.json();

    // 1. Persist user's message to DB
    const lastUserMessage = messages.findLast(m => m.role === 'user');
    if (lastUserMessage) {
      await sendMessage(ctx, conversationId, lastUserMessage.content);
    }

    // 2. Fetch full history from DB for context
    const dbMessages = await getConversationMessages(ctx, conversationId);
    const coreMessages = convertToCoreMessages(
      dbMessages.map(m => ({
        role: m.role === 'ai' ? 'assistant' : m.role,
        content: m.body
      }))
    );

    // 3. Bind tools to tenant context
    const tools = createRecoveryTools({ tenantId: ctx.tenantId, conversationId });

    // 4. Stream response
    const result = await streamText({
      model: getModel(),
      system: RECOVERY_AGENT_SYSTEM_PROMPT,
      messages: coreMessages,
      tools,
      maxSteps: 3, // Allow AI to call tools and process results
      onFinish: async ({ text }) => {
        // 5. Persist AI's final response to DB
        if (db && text) {
          await db.insert(conversationMessages).values({
            tenantId: ctx.tenantId,
            conversationId,
            role: "ai",
            body: text,
            status: "sent",
          });
        }
      },
    });

    return result.toDataStreamResponse();
  } catch (err) {
    const { status, body } = toErrorResponse(err);
    return NextResponse.json(body, { status });
  }
}
```

### 2. Ozow Adapter

**`src/lib/integrations/payments/ozow.ts`**
```ts
import crypto from "crypto";
import { AppError } from "@/shared/errors/types";

export interface PaymentProvider {
  generatePaymentLink(amount: string, reference: string, customerEmail?: string): Promise<string>;
  verifyWebhookSignature(payload: string, signature: string): boolean;
}

export class OzowAdapter implements PaymentProvider {
  private apiKey: string;
  private passKey: string;
  private siteCode: string;
  private baseUrl: string;

  constructor() {
    this.apiKey = process.env.OZOW_API_KEY || "";
    this.passKey = process.env.OZOW_PASS_KEY || "";
    this.siteCode = process.env.OZOW_SITE_CODE || "";
    this.baseUrl = process.env.OZOW_BASE_URL || "https://api.ozow.com";
  }

  async generatePaymentLink(amount: string, reference: string, customerEmail?: string): Promise<string> {
    if (!this.apiKey || !this.passKey || !this.siteCode) {
      throw new AppError("OZOW_NOT_CONFIGURED", 503, "Ozow credentials missing");
    }

    // MVP: Mocking the actual POST request to Ozow /PostPaymentRequest
    // In production, this would build a hashed request and POST to Ozow.
    const mockPaymentUrl = `https://pay.ozow.com/secure/${reference}`;
    
    // Simulate API latency
    await new Promise(resolve => setTimeout(resolve, 100));
    
    return mockPaymentUrl;
  }

  verifyWebhookSignature(payload: string, signature: string): boolean {
    if (!this.passKey) return false;
    
    // Ozow signs payloads using HMAC SHA256 with the PassKey
    const expectedSignature = crypto
      .createHmac("sha256", this.passKey)
      .update(payload)
      .digest("hex");

    return crypto.timingSafeEqual(
      Buffer.from(expectedSignature),
      Buffer.from(signature)
    );
  }
}

export const ozow = new OzowAdapter();
```

### 3. Payments Service

**`src/modules/payments/service.ts`** (Replace existing)
```ts
import { eq, and } from "drizzle-orm";
import { db } from "@/lib/db";
import { paymentRequests } from "@/lib/db/schema/payments";
import { recoveryOpportunities } from "@/lib/db/schema/recovery";
import { AppError } from "@/shared/errors/types";
import { ozow } from "@/lib/integrations/payments/ozow";

type Ctx = { tenantId: string };

export async function createPaymentRequest(ctx: Ctx, data: any) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  
  const reference = `2L-${Date.now()}`;
  
  // 1. Create DB record
  const [payReq] = await db.insert(paymentRequests).values({
    ...data,
    tenantId: ctx.tenantId,
    provider: "ozow",
    providerReference: reference,
    status: "pending"
  }).returning();

  // 2. Get payment link from Ozow
  const paymentUrl = await ozow.generatePaymentLink(data.amount, reference);

  // 3. Update record with URL (if we stored it, but for MVP we just return it)
  return { ...payReq, paymentUrl };
}

export async function getPaymentRequest(ctx: Ctx, id: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);
  const pay = await db.query.paymentRequests.findFirst({
    where: and(eq(paymentRequests.id, id), eq(paymentRequests.tenantId, ctx.tenantId))
  });
  if (!pay) throw new AppError("NOT_FOUND", 404, "Payment request not found");
  return pay;
}

export async function processPaymentWebhook(ctx: Ctx, payload: any, signature: string) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  // 1. Verify Signature
  const isValid = ozow.verifyWebhookSignature(JSON.stringify(payload), signature);
  if (!isValid) {
    throw new AppError("UNAUTHORIZED", 401, "Invalid signature");
  }

  // Ozow sends Status: "Complete" (case-sensitive usually, but let's be safe)
  if (payload.status?.toLowerCase() !== "complete") {
    return { status: "ignored", reason: "Not complete" };
  }

  const reference = payload.transactionreference;

  // 2. Idempotency Check
  const existing = await db.query.paymentRequests.findFirst({
    where: eq(paymentRequests.providerReference, reference)
  });

  if (!existing) {
    throw new AppError("NOT_FOUND", 404, "Payment reference not found");
  }

  if (existing.status === "paid") {
    return { status: "duplicate" };
  }

  // 3. Update Payment Status
  const [updatedPayment] = await db.update(paymentRequests).set({
    status: "paid",
    verifiedAt: new Date()
  }).where(eq(paymentRequests.id, existing.id)).returning();

  // 4. Update Opportunity Status (Revenue Recovered!)
  if (updatedPayment.opportunityId) {
    await db.update(recoveryOpportunities).set({
      status: "recovered"
    }).where(eq(recoveryOpportunities.id, updatedPayment.opportunityId));
  }

  return { status: "verified", paymentId: updatedPayment.id };
}
```

```ts
import { eq, and, ne, sql } from "drizzle-orm";
import { db } from "@/lib/db";
import { paymentRequests } from "@/lib/db/schema/payments";
import { recoveryOpportunities } from "@/lib/db/schema/recovery";
import { campaigns } from "@/lib/db/schema/campaigns";
import { AppError } from "@/shared/errors/types";

type Ctx = { tenantId: string };

export async function getDashboardMetrics(ctx: Ctx) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  // 1. Total Recovered Revenue (Verified only)
  const paidPayments = await db.query.paymentRequests.findMany({
    where: and(eq(paymentRequests.tenantId, ctx.tenantId), eq(paymentRequests.status, "paid")),
  });
  const totalRecovered = paidPayments.reduce((sum, p) => sum + parseFloat(p.amount), 0);

  // 2. Total Recoverable Pipeline (Active opportunities)
  const activeOpps = await db.query.recoveryOpportunities.findMany({
    where: and(
      eq(recoveryOpportunities.tenantId, ctx.tenantId),
      ne(recoveryOpportunities.status, "recovered"),
      ne(recoveryOpportunities.status, "declined")
    ),
  });
  const totalRecoverable = activeOpps.reduce((sum, o) => sum + parseFloat(o.estimatedValue || "0"), 0);

  // 3. Recovery Rate
  const recoveredOpps = await db.query.recoveryOpportunities.findMany({
    where: and(eq(recoveryOpportunities.tenantId, ctx.tenantId), eq(recoveryOpportunities.status, "recovered")),
  });
  const declinedOpps = await db.query.recoveryOpportunities.findMany({
    where: and(eq(recoveryOpportunities.tenantId, ctx.tenantId), eq(recoveryOpportunities.status, "declined")),
  });
  const totalResolved = recoveredOpps.length + declinedOpps.length;
  const recoveryRate = totalResolved > 0 ? (recoveredOpps.length / totalResolved) * 100 : 0;

  // 4. Funnel Counts
  const allOpps = await db.query.recoveryOpportunities.findMany({
    where: eq(recoveryOpportunities.tenantId, ctx.tenantId),
  });
  
  const contactedOpps = allOpps.filter(o => ["contacted", "engaged", "negotiating", "recovered"].includes(o.status)).length;
  const engagedOpps = allOpps.filter(o => ["engaged", "negotiating", "recovered"].includes(o.status)).length;

  // 5. Active Campaigns
  const activeCampaigns = await db.query.campaigns.findMany({
    where: and(eq(campaigns.tenantId, ctx.tenantId), eq(campaigns.status, "active")),
  });

  return {
    totalRecovered,
    totalRecoverable,
    recoveryRate,
    funnel: {
      total: allOpps.length,
      contacted: contactedOpps,
      engaged: engagedOpps,
      recovered: recoveredOpps.length,
    },
    activeCampaigns: activeCampaigns.length,
  };
}
```

## Top 5 Risks for Phase 9

2. **DB Query Performance** — We are fetching all opportunities and payments into memory to calculate sums. For MVP (<10k records), this is fine. In production, we must use SQL `SUM()` and `GROUP BY` aggregations.
3. **Missing 7-day Delta** — The mockup shows "+18.6% vs past 7 days". I omitted this for MVP because calculating time-series deltas requires a `paidAt` timestamp comparison which adds query complexity. It's a quick add for Phase 11.
4. **Monotonic Funnel Rule** — The PRD states funnels must be monotonic. The SQL doesn't enforce this, but the UI logic ensures `Contacted <= Total` and `Engaged <= Contacted`.
5. **Empty States** — If a tenant has 0 opportunities, the charts will show 0s. The `recharts` BarChart might render weirdly with all 0s. We may need to set a `minTickGap` or default value.

### 1. MCP Registry & Handlers

**`src/lib/mcp/registry.ts`**
```ts
import { z } from "zod";
import { listCustomers } from "@/modules/customers/service";
import { listCampaigns } from "@/modules/campaigns/service";
import { getDashboardMetrics } from "@/modules/analytics/service";
import { logger } from "@/lib/logging/logger";

// JSON-RPC types
export type JsonRpcRequest = {
  jsonrpc: "2.0";
  id: string | number;
  method: string;
  params?: any;
};

export type JsonRpcResponse = {
  jsonrpc: "2.0";
  id: string | number;
  result?: any;
  error?: { code: number; message: string };
};

type ToolDef = {
  description: string;
  schema: z.ZodObject<any>;
  roles: Array<"owner" | "admin" | "member">;
  handler: (ctx: any, args: any) => Promise<any>;
};

export const mcpTools: Record<string, ToolDef> = {
  "customers.search": {
    description: "Search and list customers in the tenant.",
    schema: z.object({ limit: z.number().optional().default(50) }),
    roles: ["owner", "admin", "member"],
    handler: async (ctx, args) => {
      const customers = await listCustomers(ctx);
      return { customers };
    },
  },
  "campaigns.list": {
    description: "List all campaigns for the tenant.",
    schema: z.object({}),
    roles: ["owner", "admin", "member"],
    handler: async (ctx, args) => {
      const campaigns = await listCampaigns(ctx);
      return { campaigns };
    },
  },
  "analytics.summary": {
    description: "Get high-level dashboard metrics (recovered revenue, pipeline, etc).",
    schema: z.object({}),
    roles: ["owner", "admin", "member"],
    handler: async (ctx, args) => {
      return await getDashboardMetrics(ctx);
    },
  },
  // Example of an admin-only tool
  "diagnostics.run": {
    description: "Run system diagnostics (Admin/Owner only).",
    schema: z.object({}),
    roles: ["owner", "admin"],
    handler: async (ctx, args) => {
      return { status: "healthy", dbConnected: !!process.env.DATABASE_URL };
    },
  },
};

export function listMcpTools() {
  return Object.entries(mcpTools).map(([name, def]) => ({
    name,
    description: def.description,
    inputSchema: {
      type: "object",
      properties: def.schema.shape,
    },
  }));
}

export async function callMcpTool(
  ctx: { tenantId: string; role: "owner" | "admin" | "member" },
  toolName: string,
  args: any
): Promise<JsonRpcResponse> {
  const def = mcpTools[toolName];
  if (!def) {
    return { jsonrpc: "2.0", id: "unknown", error: { code: -32601, message: "Tool not found" } };
  }

  // RBAC Check
  if (!def.roles.includes(ctx.role)) {
    logger("warn", "mcp.forbidden", { toolName, role: ctx.role });
    return { jsonrpc: "2.0", id: "unknown", error: { code: -32603, message: "Forbidden: Insufficient role" } };
  }

  // Zod Validation
  const parsed = def.schema.safeParse(args);
  if (!parsed.success) {
    return { jsonrpc: "2.0", id: "unknown", error: { code: -32602, message: parsed.error.message } };
  }

  try {
    logger("info", "mcp.tool_call", { toolName, tenantId: ctx.tenantId });
    const result = await def.handler(ctx, parsed.data);
    return { jsonrpc: "2.0", id: "unknown", result };
  } catch (err: any) {
    return { 
      jsonrpc: "2.0", 
      id: "unknown", 
      error: { code: -32000, message: err.message || "Execution error" } 
    };
  }
}
```

### 2. MCP API Route (JSON-RPC over HTTP)

**`src/app/api/mcp/[...route]/route.ts`**
```ts
import { NextResponse } from "next/server";
import { auth } from "@clerk/nextjs/server";
import { getTenantContext, requireRole } from "@/modules/tenants/service";
import { listMcpTools, callMcpTool, JsonRpcRequest, JsonRpcResponse } from "@/lib/mcp/registry";
import { logger } from "@/lib/logging/logger";

export const dynamic = "force-dynamic";
export const runtime = "nodejs";

export async function POST(req: Request) {
  let rpcReq: JsonRpcRequest;
  try {
    rpcReq = await req.json();
  } catch {
    return NextResponse.json({ error: "Invalid JSON" }, { status: 400 });
  }

  const { userId } = auth();
  if (!userId) {
    return NextResponse.json({ 
      jsonrpc: "2.0", 
      id: rpcReq.id, 
      error: { code: -32001, message: "Unauthorized" } 
    }, { status: 401 });
  }

  try {
    // 1. Handle JSON-RPC methods
    if (rpcReq.method === "initialize") {
      return NextResponse.json({ 
        jsonrpc: "2.0", 
        id: rpcReq.id, 
        result: { protocolVersion: "2024-11-05", capabilities: { tools: {} } } 
      });
    }

    if (rpcReq.method === "tools/list") {
      return NextResponse.json({ 
        jsonrpc: "2.0", 
        id: rpcReq.id, 
        result: { tools: listMcpTools() } 
      });
    }

    if (rpcReq.method === "tools/call") {
      const { name, arguments: args } = rpcReq.params || {};
      
      // We need role for RBAC, so we use requireRole with all roles allowed at this stage.
      // The callMcpTool function does the specific role check per tool.
      const ctx = await requireRole(["owner", "admin", "member"]);
      
      const result = await callMcpTool(ctx, name, args);
      
      // Reconstruct with original ID
      const response: JsonRpcResponse = { ...result, id: rpcReq.id };
      return NextResponse.json(response);
    }

    // Method not found
    return NextResponse.json({ 
      jsonrpc: "2.0", 
      id: rpcReq.id, 
      error: { code: -32601, message: "Method not found" } 
    }, { status: 400 });

  } catch (err: any) {
    logger("error", "mcp.error", { method: rpcReq.method, error: err.message });
    
    // Handle auth/tenant errors gracefully for JSON-RPC
    if (err.code === "UNAUTHENTICATED" || err.code === "USER_NOT_FOUND") {
      return NextResponse.json({ 
        jsonrpc: "2.0", 
        id: rpcReq.id, 
        error: { code: -32001, message: "Unauthorized" } 
      }, { status: 401 });
    }
    
    return NextResponse.json({ 
      jsonrpc: "2.0", 
      id: rpcReq.id, 
      error: { code: -32000, message: err.message || "Internal error" } 
    }, { status: 500 });
  }
}
```

## Top 5 Risks for Phase 10
1. **MCP Transport Spec** — The official MCP spec uses SSE or custom stdio transports for communication. I implemented a standard JSON-RPC 2.0 HTTP POST handler, which is compatible with the protocol payload structure but bypasses the official SDK's transport layer. This is fine for a custom REST-like integration, but if you want to use the `@modelcontextprotocol/sdk` strictly, we'd need to adapt the route to use `StreamableHTTPServerTransport`.
2. **Clerk Auth on External Agents** — External AI agents (like Claude Desktop) won't have a Clerk session cookie. To make this truly useful externally, we need to support Bearer tokens (e.g., `Authorization: Bearer <clerk_api_key>`) which Clerk supports via Backend API, but it requires a different auth extraction method in the route. For now, this works for internal authenticated dashboard calls.
3. **Zod Schema Output** — `def.schema.shape` might not perfectly map to JSON Schema for strict MCP clients. We might need to use `zod-to-json-schema` if clients complain about the input schema format.
4. **Error Codes** — JSON-RPC has specific error code ranges (-32000 to -32099 for server errors). I mapped RBAC to -32603 (Generic error) because there isn't a standard JSON-RPC code for "Forbidden". We could use -32001 for Unauthorized and -32003 for Forbidden to be more descriptive.
5. **Missing Audit Table** — We are logging MCP calls to the console via `logger`, but the PRD mentions an `audit_logs` table. We should migrate that in Phase 12.

Report back once Vercel is green and tests pass. Then we move to **Phase 11 (Testing & E2E)**.

### 2. Rate Limiter Utility

**`src/lib/middleware/rate-limit.ts`**
```ts
import { Ratelimit } from "@upstash/ratelimit";
import { Redis } from "@upstash/redis";

let ratelimit: Ratelimit | null = null;

function getLimiter() {
  if (ratelimit) return ratelimit;
  
  const url = process.env.UPSTASH_REDIS_REST_URL;
  const token = process.env.UPSTASH_REDIS_REST_TOKEN;
  
  if (!url || !token) return null;
  
  ratelimit = new Ratelimit({
    redis: new Redis({ url, token }),
    limiter: Ratelimit.slidingWindow(10, "10 s"),
    analytics: true,
  });
  
  return ratelimit;
}

export async function rateLimit(req: Request): Promise<boolean> {
  const limiter = getLimiter();
  
  // Bypass if not configured (preserves env -i build)
  if (!limiter) return true;
  
  // Use IP address as identifier
  const ip = req.headers.get("x-forwarded-for") || "anonymous";
  const { success } = await limiter.limit(ip);
  
  return success;
}
```

### 4. POPIA Opt-Out Logic

Edit **`src/modules/conversations/service.ts`**. Replace the `receiveMessage` function with this updated version that handles "STOP":

```ts
export async function receiveMessage(ctx: Ctx, payload: any) {
  if (!db) throw new AppError("DATABASE_NOT_CONFIGURED", 503);

  const externalId = payload.key?.id;
  const fromPhone = payload.key?.remoteJid?.split("@")[0];
  const body = payload.message?.conversation || payload.message?.extendedTextMessage?.text;

  if (!externalId || !fromPhone || !body) {
    throw new AppError("INVALID_WEBHOOK", 400, "Missing required fields");
  }

  // 1. Idempotency check
  const existing = await db.query.webhookEvents.findFirst({
    where: eq(webhookEvents.externalId, externalId)
  });
  if (existing) {
    return { status: "duplicate" };
  }

  // Find customer by phone
  const customer = await db.query.customers.findFirst({
    where: and(eq(customers.tenantId, ctx.tenantId), eq(customers.phone, fromPhone))
  });

  // Persist webhook event regardless
  await db.insert(webhookEvents).values({
    tenantId: ctx.tenantId,
    externalId,
    provider: "evolution",
    payload
  });

  if (!customer) {
    return { status: "unknown_customer" };
  }

  // 2. POPIA Opt-Out Handling
  if (body.trim().toLowerCase() === "stop") {
    await db.update(customers)
      .set({ isSuppressed: true })
      .where(eq(customers.id, customer.id));

    let conversation = await db.query.conversations.findFirst({
      where: and(eq(conversations.customerId, customer.id), eq(conversations.tenantId, ctx.tenantId))
    });
    if (!conversation) {
      const [newConv] = await db.insert(conversations).values({
        tenantId: ctx.tenantId, customerId: customer.id, status: "closed"
      }).returning();
      conversation = newConv;
    }

    await db.insert(conversationMessages).values({
      tenantId: ctx.tenantId,
      conversationId: conversation.id,
      role: "system",
      body: "Customer opted out (replied STOP). Suppression applied.",
      status: "received",
      externalId,
    });

    return { status: "opted_out" };
  }

  // 3. Normal Conversation Flow
  let conversation = await db.query.conversations.findFirst({
    where: and(eq(conversations.customerId, customer.id), eq(conversations.tenantId, ctx.tenantId))
  });

  if (!conversation) {
    const [newConv] = await db.insert(conversations).values({
      tenantId: ctx.tenantId, customerId: customer.id, status: "active"
    }).returning();
    conversation = newConv;
  }

  const [message] = await db.insert(conversationMessages).values({
    tenantId: ctx.tenantId,
    conversationId: conversation.id,
    role: "customer",
    body,
    status: "received",
    externalId,
  }).returning();

  return { status: "created", message };
}
```

## Top 5 Risks for Phase 12
1. **Rate Limiting Cold Starts** — Upstash adds latency. If the Redis connection is slow, the `/api/health` check might timeout. The sliding window is fast enough that this shouldn't be an issue, but monitor it.
2. **Drizzle Migration Drift** — If you already used `db:push` on your Neon database, running `db:migrate` might conflict if the schema isn't perfectly synced. It's best to run this on a fresh database, or just keep using `push` for dev until you officially launch.
3. **Opt-Out Edge Cases** — We only catch exactly "stop". Customers might type "STOP!", "unsubscribe", or "please stop". We should eventually use a regex or AI intent detection to catch these, but hardcoding "stop" covers the legal baseline.
4. **CSP Strictness** — If you try to load images from a new domain (e.g., a CMS), the CSP will block it. You'll need to update `next.config.ts` to whitelist the domain.
5. **Vercel Env Vars** — You must manually add all the secrets (`CLERK_SECRET_KEY`, `DATABASE_URL`, etc.) to the Vercel Project Settings → Environment Variables. The build will pass without them, but the app will 503 at runtime.
